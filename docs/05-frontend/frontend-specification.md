**Экран выбора категорий кэшбэка**



# 1. Пользовательский сценарий

## 1.1 Контекст и лимиты

|**Тип пользователя**|**Макс. категорий**|**Источник данных**|
|-|-|-|
|Без подписки|3|Поле subscription в профиле|
|С подпиской|4|Поле subscription в профиле|

## 1.2 Happy path

•       Пользователь открывает экран выбора категорий.

•       Параллельно запрашиваются: список категорий (GET /cashback/categories) и текущий выбор (GET /cashback/selection). Пока данные грузятся, показываются скелетоны.

•       Список загружен: предвыбранные категории отмечены, остальные активны.

•       Пользователь отмечает/снимает категории до достижения лимита.

•       Нажимает «Готово» → кнопка переходит в loading → PUT /cashback/selection.

•       При успехе открывается окно с оценкой.

•       Пользователь выбирает звёзды → POST /cashback/rating (fire-and-forget) → окно с оценкой закрывается → сценарий завершён.

 

## 1.3 Альтернативные пути

|**Ситуация**|**Поведение**|
|-|-|
|«Закрыть» без изменений|Экран закрывается, запросов нет|
|«Закрыть» с несохранёнными изменениями|Диалог подтверждения (п. 2.6)|
|Закрытие окна с оценкой без оценки|Категории уже сохранены, рейтинг не отправляется, сценарий завершён|
|Тап «Условия программы лояльности»|WebView/браузер, экран выбора остаётся в стеке|
|Ошибка сети при открытии (нет кэша)|Экран ошибки с кнопкой «Повторить»|
|Ошибка сети при нажатии «Готово»|Toast, кнопка снова активна, данные не теряются|
|Пользователь уже выбирал категории в этом месяце|Экран открывается с предзаполненным выбором, изменение доступно|

# 3. Источники данных и интеграция

## 3.1 Запросы при открытии экрана

*Оба запроса выполняются параллельно.* 

|**Запрос**|**Метод**|**Описание**|**Данные**|
|-|-|-|-|
|GET /cashback/categories|GET|Список доступных категорий на текущий месяц|id, name, percent, iconUrl, description, termsUrl, preselected|
|GET /cashback/selection|GET|Текущий выбор пользователя (если уже выбирал)|month, categories: [id, ...]|
|Профиль пользователя|Из локального стора|Тип подписки для определения лимита|subscription: true/false|

## 3.2 Запросы по действиям пользователя

|**Действие**|**Метод**|**Endpoint**|
|-|-|-|
|Нажатие «Готово»|PUT|/cashback/selection|
|Выбор звезды|POST|/cashback/rating|
|Тап «?» на категории|—|—|

## 3.4 Кэширование

|**Данные**|**Стратегия**|**TTL**|**Инвалидация**|
|-|-|-|-|
|GET /cashback/categories|Stale-while-revalidate: показать кэш сразу, обновить в фоне|1 час|Смена аккаунта; смена месяца; 404/410 на категорию из кэша; принудительный pull-to-refresh|
|GET /cashback/selection|Не кэшировать|—|Запрашивать при каждом открытии экрана|
|Иконки категорий|HTTP Cache-Control (CDN)|По заголовкам CDN|Версионирование в URL|
|Профиль (subscription)|Локальный стор|До обновления профиля|При выходе из аккаунта|

## 3.5 Офлайн-сценарии

|**Ситуация**|**Поведение**|
|-|-|
|Нет сети, кэш категорий есть|Показать кэшированный список + баннер «Данные могут быть устаревшими»|
|Нет сети, кэша нет|Экран ошибки: иконка отсутствия сети + текст + кнопка «Повторить»|
|Нет сети при нажатии «Готово»|Toast «Нет соединения», кнопка активна, данные не теряются|
|Соединение восстановилось|Повторить последний неудавшийся запрос автоматически (если пользователь ещё на экране)|

## 5. Недостающие состояния на макетах

На макетах показаны три состояния: пустой список, частичный выбор (4 категории), оценка. Не хватает следующих:

**Состояния экрана**

1. **Загрузка данных.** Когда данные подгружаются с сервера, нужен какой-то  скелетон, чтобы экран не дергался.

2. **Ошибка загрузки**. Если сервер не ответил или вернул ошибку. Нужен экран с сообщением и кнопкой «Повторить».

3. **Пользователь уже сделал выбор в этом месяце**. Не понятно, что делать: он может только смотреть или можно выбрать заново?

4. **Пользователь без подписки**. У него другой лимит (3 категории, а не 4), но на макетах везде показано только 4.

5. **Выбрано меньше максимума**. Что происходит при нажатии «Готово» с 0, 1 или 2 выбранными категориями.

**Состояния окна с оценкой**

1. **Состояние после выбора звезды до закрытия Е**сть ли анимация подтверждения после выбора звезды или окно закрывается мгновенно.

2. **Ошибка загрузки** Если сервер не отвечает, то тоже нужен экран ошибки и возможность повторить.

**Навигация**

1. **Подтверждение при выходе** Диалог нужен только если пользователь что-то поменял. Если он выбрал и потом всё убрал, то подтверждение не нужно, потому что ничего не изменилось.
