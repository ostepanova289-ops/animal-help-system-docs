# Вопросы для сбора требований

| Вопрос и цель | Кому задавать | Почему именно этому стейкхолдеру |
| - | - | - |
| **Какие данные о потенциальном владельце вам действительно необходимы для принятия решения?**<br>*Цель: Определить обязательные поля формы и избежать избыточных требований* | **Куратор / Приют**<br><br>**Администратор системы** | **[Куратор / Приют]** Именно он принимает решение и знает, какие данные реально влияют на выбор<br><br>**[Администратор системы]** Знает, какие данные уже собирает система и что технически хранится |
| **Какие признаки в заявке говорят вам о высокой вероятности успешного пристройства?**<br>*Цель: Выявить критерии оценки заявки и возможные бизнес-правила* | **Куратор / Приют**<br><br>**Представитель по работе с приютами** | **[Куратор / Приют]** Обладает опытом и интуицией, может назвать паттерны успешных пристройств<br><br>**[Представитель по работе с приютами]** Видит картину по нескольким приютам, может выявить общие паттерны |
| **Бывали ли случаи, когда информации в заявке оказалось недостаточно? Чего именно не хватало?**<br>*Цель: Найти пробелы в текущей модели данных* | **Куратор / Приют** | **[Куратор / Приют]** Имеет опыт реальных заявок и помнит конкретные случаи |
| **Нужна ли предварительная фильтрация заявителей до того, как куратор увидит заявку?**<br>*Цель: Понять необходимость автоматических проверок или скоринга* | **Куратор / Приют**<br><br>**Product Owner** | **[Куратор / Приют]** Скажет, нужна ли ему такая фильтрация и снизит ли она нагрузку<br><br>**[Product Owner]** Принимает решение о сложности реализации vs ценности функции |
| **Что должно происходить после подачи заявки: автоматическое подтверждение, звонок, чат внутри системы?**<br>*Цель: Определить ожидаемый пользовательский путь после отправки формы* | **Потенциальный пользователь**<br><br>**Куратор / Приют**<br><br>**Product Owner** | **[Потенциальный пользователь]** Он проходит этот путь, знает, что ему важно получить после отправки<br><br>**[Куратор / Приют]** Должен подтвердить, какой канал связи ему удобен для ответа<br><br>**[Product Owner]** Принимает решение об объёме функционала |
| **Сколько времени вы готовы ждать ответа после подачи заявки?**<br>*Цель: Определить требования к SLA и уведомлениям* | **Потенциальный пользователь**<br><br>**Куратор / Приют** | **[Потенциальный пользователь]** Формирует ожидания со стороны спроса — его терпение определяет SLA<br><br>**[Куратор / Приют]** Формирует реалистичный SLA со стороны предложения, сколько им нужно времени |
| **В каких случаях вы отклоняете заявку на пристройство?**<br>*Цель: Выявить бизнес-правила отказа и возможные статусы* | **Куратор / Приют** | **[Куратор / Приют]** Только он принимает решение об отказе и знает реальные причины |
| **Нужно ли фиксировать причину отказа в системе? Должна ли она быть видна заявителю?**<br>*Цель: Определить требования к прозрачности и истории изменений* | **Куратор / Приют**<br><br>**Потенциальный пользователь**<br><br>**Product Owner** | **[Куратор / Приют]** Решает, готов ли он публично объяснять отказы<br><br>**[Потенциальный пользователь]** Хочет ли он знать причину, влияет на UX и доверие к платформе<br><br>**[Product Owner]** Оценивает риски: публичные причины отказа могут создать конфликты |
| **Что должно происходить с другими активными заявками, если животное уже пристроено?**<br>*Цель: Проверить корректность сценария массового закрытия заявок* | **Куратор / Приют**<br><br>**Потенциальный пользователь** | **[Куратор / Приют]** Знает текущий процесс и ожидает конкретного поведения системы<br><br>**[Потенциальный пользователь]** Должен получить корректное уведомление, проверяем его ожидания |
| **Нужна ли система напоминаний куратору о необработанных заявках? Через какое время?**<br>*Цель: Выявить требования к управлению просроченными заявками* | **Куратор / Приют**<br><br>**Product Owner** | **[Куратор / Приют]** Оценит, раздражают ли его напоминания или помогают не забыть<br><br>**[Product Owner]** Связывает с KPI «60% заявок за 14 дней» — напоминания могут быть ключевым инструментом |
| **Хотели бы вы видеть историю предыдущих заявок пользователя (если он уже пытался взять животное)?**<br>*Цель: Определить необходимость хранения истории взаимодействий* | **Куратор / Приют**<br><br>**Администратор системы**<br><br>**Product Owner** | **[Куратор / Приют]** Решает, повлияет ли история на его решение (доверие к заявителю)<br><br>**[Администратор системы]** Оценивает сложность хранения и доступа к данным<br><br>**[Product Owner]** Принимает решение о приоритете функции для MVP |
| **Какие риски вы видите в текущем процессе пристройства?**<br>*Цель: Выявить скрытые проблемы и граничные случаи* | **Куратор / Приют**<br><br>**Представитель по работе с приютами**<br><br>**Администратор системы** | **[Куратор / Приют]** Работает с процессом ежедневно — знает болевые точки из практики<br><br>**[Представитель по работе с приютами]** Видит риски на уровне нескольких организаций<br><br>**[Администратор системы]** Видит технические риски: дубли, мошенничество, некорректные данные |
| **Какие метрики по заявкам на пристройство для вас важны (конверсия, срок рассмотрения и т.д.)?**<br>*Цель: Определить требования к аналитике и KPI* | **Product Owner**<br><br>**Инвестор / Заказчик проекта**<br><br>**Представитель по работе с приютами** | **[Product Owner]** Отвечает за метрики продукта и KPI из концепции<br><br>**[Инвестор / Заказчик проекта]** Интересуется эффективностью вложений — хочет видеть измеримые результаты<br><br>**[Представитель по работе с приютами]** Может добавить операционные метрики, важные для приютов |
