# Функциональные требования

## UC-1 — Регистрация пользователя с выбором роли

| Поле | Значение |
| - | - |
| ID | UC-1 |
| Название | Регистрация пользователя с выбором роли |
| Акторы | • Незарегистрированный пользователь<br>• Система (Auth Service)<br>• Администратор системы (для модерации ролей «Приют» и «Куратор») |
| Предусловия | • Пользователь не авторизован в системе<br>• Страница регистрации доступна<br>• Пользователь имеет действующий номер телефона |
| Постусловия (Успех) | • Учётная запись создана в базе данных<br>• Пользователю присвоена выбранная роль (Волонтёр / Помощник) или роль поставлена на модерацию (Приют / Куратор)<br>• Номер телефона подтверждён<br>• Пользователь перенаправлен на страницу заполнения профиля |
| Постусловия (Неудача) | • Учётная запись не создана<br>• Пользователю отображается сообщение об ошибке с указанием причины<br>• Данные формы сохранены для повторного ввода |
| Основной поток | 1. Пользователь открывает страницу регистрации.<br>2. Система отображает форму регистрации.<br>3. Система отображает поля: номер телефона, имя/название организации.<br>4. Система отображает выбор роли: Приют, Куратор, Волонтёр, Помощник.<br>5. Пользователь вводит номер телефона и выбирает роль.<br>6. Пользователь нажимает кнопку «Продолжить».<br>7. Система проверяет корректность номера телефона и его уникальность в базе данных.<br>8. Система отправляет одноразовый SMS-код подтверждения.<br>9. Пользователь вводит полученный код.<br>10. Система проверяет корректность кода подтверждения.<br>11. Если выбрана роль «Приют» или «Куратор», система создаёт аккаунт со статусом «Ожидает модерации» и уведомляет администратора.<br>12. Если выбрана роль «Волонтёр» или «Помощник», система активирует аккаунт.<br>13. Система подтверждает номер телефона пользователя.<br>14. Пользователь перенаправляется на страницу заполнения профиля. |
| Альтернативный поток | **Номер телефона уже зарегистрирован**<br>Точка входа: Шаг 7<br>7a. Система обнаруживает, что номер телефона уже существует в базе данных.<br>7b. Система отображает сообщение: «Пользователь с таким номером телефона уже зарегистрирован».<br>7c. Пользователь может перейти на страницу входа.<br><br>**SMS-код недействителен**<br>Точка входа: Шаг 10<br>10a. Пользователь вводит неверный или просроченный код.<br>10b. Система отображает сообщение: «Код подтверждения недействителен».<br>10c. Система предлагает запросить новый код. |
| Исключительный поток | **Сервис SMS-рассылки недоступен**<br>Точка входа: Шаг 8<br>8a. Сервис отправки SMS не отвечает.<br>8b. Система сохраняет задачу отправки в очередь для повторной попытки.<br>8c. Аккаунт создаётся со статусом «Телефон не подтверждён».<br>8d. Система информирует пользователя: «Код подтверждения будет отправлен повторно через несколько минут». |
| Бизнес-правила | • BR-01: Номер телефона должен быть уникальным в системе.<br>• BR-02: Роли «Приют» и «Куратор» требуют модерации администратором в течение 48 часов.<br>• BR-03: Одноразовый SMS-код действует 5 минут.<br>• BR-04: Пользователь не может войти в систему до подтверждения номера телефона.<br>• BR-05: После 5 неверных попыток ввода SMS-кода отправка временно блокируется на 15 минут |

## UC-2 — Создание карточки животного

| Поле | Значение |
| - | - |
| ID | UC-2 |
| Название | Создание карточки животного |
| Акторы | • Куратор или представитель Приюта (авторизованный, роль подтверждена)<br>• Система |
| Предусловия | • Пользователь авторизован с ролью «Куратор» или «Приют» (статус аккаунта — активный)<br>• Пользователь находится в разделе «Мои животные» |
| Постусловия (Успех) | • Карточка животного сохранена в базе данных с уникальным идентификатором<br>• Карточке присвоен статус «Ищет дом» (по умолчанию) или иной, указанный пользователем<br>• Карточка опубликована и доступна для просмотра другим пользователям системы, если статус не равен «Пристроен»<br>• Карточка со статусом «Пристроен» скрывается из публичного каталога, но сохраняется в системе<br>• В истории изменений зафиксировано создание карточки: дата, автор, начальные данные |
| Постусловия (Неудача) | • Карточка не сохранена<br>• Система отображает ошибку валидации с указанием незаполненных обязательных полей<br>• Введённые данные сохранены в форме для доработки |
| Основной поток | 1. Пользователь нажимает кнопку «Добавить животное».<br>2. Система отображает форму создания карточки.<br>3. Пользователь заполняет обязательные поля: кличка (макс 50 символов) (или «без клички»), вид (кошка/собака/другое), пол(жен/муж), приблизительный возраст, описание (макс 1000 символов).<br>4. Пользователь выбирает статус: «На лечении», «Ищет дом», «Передержка», «Пристроен».<br>5. Пользователь загружает минимум 1 фотографию (допустимые форматы: JPG, PNG, WebP; максимальный размер: 5 МБ каждая).<br>6. Пользователь заполняет информацию о состоянии здоровья: вакцинирован (да/нет/неизвестно), стерилизован (да/нет/неизвестно), наличие заболеваний.<br>7. Пользователь указывает город/регион нахождения животного.<br>8. Пользователь нажимает «Сохранить и опубликовать».<br>9. Система валидирует данные: проверяет заполненность обязательных полей, форматы файлов, размер фото.<br>10. Система сохраняет карточку и присваивает уникальный ID (формат: ANIMAL-XXXXX).<br>11. Если выбран статус «Пристроен», система автоматически скрывает карточку из публичного каталога.<br>11. Система фиксирует событие создания карточки в истории изменений.<br>13. Система отображает сообщение: «Карточка успешно создана».<br>14. Система перенаправляет пользователя на страницу карточки животного |
| Альтернативный поток | **Карточка скрывается после пристройства**<br>Точка входа: Шаг 11<br>11a. Система исключает карточку из общего каталога животных.<br>11b. Карточка остаётся доступной автору и администратору в архиве.<br><br>**Загрузка фото не удалась (превышен размер)**<br>Точка входа: Шаг 5<br>5a. Пользователь выбирает файл размером более 5 МБ.<br>5b. Система отображает ошибку: «Файл превышает допустимый размер 5 МБ. Уменьшите изображение».<br>5c. Поле загрузки остаётся доступным, остальные данные формы сохранены. |
| Исключительный поток | **Ошибка сохранения в базе данных**<br>Точка входа: Шаг 10<br>10a. Ошибка при сохранении данных в БД.<br>10b. Система отображает сообщение: «Не удалось сохранить карточку. Попробуйте ещё раз».<br>10c. Система сохраняет введённые данные во временном хранилище сессии.<br>10d. Use Case завершается. Данные формы не теряются. |
| Бизнес-правила | • BR-01: Создавать карточки могут только пользователи с подтверждёнными ролями «Куратор» или «Приют».<br>• BR-02: Обязательные поля: кличка, вид животного, пол, возраст, описание, минимум 1 фото, город.<br>• BR-03: Допустимые форматы фото: JPG, PNG, WebP. Максимальный размер — 5 МБ на файл, не более 10 фото.<br>• BR-04: Каждое изменение данных карточки фиксируется в истории изменений.<br>• BR-05: Статус «Пристроен» может быть выставлен только автором карточки или администратором.<br>• BR-06: Карточки со статусом «Пристроен» автоматически скрываются из публичного каталога и переводятся в архив. |

## UC-3 — Публикация заявки на помощь

| Поле | Значение |
| - | - |
| ID | UC-3 |
| Название | Публикация заявки на помощь |
| Акторы | • Куратор или представитель Приюта (авторизованный, роль подтверждена)<br>• Система<br>• Волонтёры и Помощники (получают уведомления) |
| Предусловия | • Пользователь авторизован с ролью «Куратор» или «Приют»<br>• В системе существует карточка животного, к которой привязывается заявка (или заявка создаётся без привязки к конкретному животному)<br>• Пользователь находится на странице карточки животного или в разделе «Заявки на помощь» |
| Постусловия (Успех) | • Заявка сохранена с уникальным идентификатором (формат: HELP-XXXXX)<br>• Заявка опубликована в общем списке заявок на помощь<br>• Зарегистрированные волонтёры и помощники получают уведомление о новой заявке (если включены уведомления)<br>• Статус заявки: «Открыта»<br>• В истории изменений карточки животного зафиксирована новая заявка |
| Постусловия (Неудача) | • Заявка не сохранена<br>• Отображается ошибка с указанием незаполненных полей<br>• Введённые данные сохранены в форме |
| Основной поток | 1. Пользователь нажимает «Создать заявку на помощь» (на странице карточки животного или в разделе заявок).<br>2. Система отображает форму создания заявки.<br>3. Пользователь выбирает тип помощи из списка: Лечение, Корм, Перевозка, Передержка, Финансовая помощь, Другое.<br>4. Пользователь заполняет заголовок заявки (макс. 100 символов) и подробное описание (макс. 1000 символов).<br>5. Пользователь устанавливает срочность: Срочно (выделяется визуально), Обычная.<br>6. При необходимости пользователь указывает требуемую сумму (для типа «Финансовая помощь» или «Лечение»).<br>7. При необходимости пользователь прикрепляет карточку животного.<br>8. Пользователь устанавливает дедлайн (опционально).<br>9. Пользователь нажимает «Опубликовать заявку».<br>10. Система валидирует данные: тип, заголовок, описание.<br>11. Система сохраняет заявку со статусом «Открыта» и присваивает ID.<br>12. Система рассылает уведомления волонтёрам и помощникам.<br>13. Система перенаправляет пользователя на страницу созданной заявки. |
| Альтернативный поток | **Откликнуться на заявку (Волонтёр / Помощник)**<br>Точка входа: После публикации — отдельный сценарий взаимодействия<br>1a. Волонтёр или Помощник открывает список заявок на помощь.<br>1b. Пользователь выбирает заявку и нажимает «Откликнуться».<br>1c. Система записывает отклик, меняет статус заявки на «В работе», уведомляет автора заявки.<br><br>**Закрытие заявки после выполнения**<br>Точка входа: После статуса «В работе»<br>1a. Автор заявки или волонтёр нажимает «Отметить выполненной».<br>1b. Система запрашивает подтверждение и опциональный комментарий/фото-отчёт.<br>1c. Система переводит статус в «Закрыта», фиксирует дату и исполнителя в истории. |
| Исключительный поток | **Ошибка рассылки уведомлений**<br>Точка входа: Шаг 12<br>12a. Сервис уведомлений недоступен.<br>12b. Система сохраняет задачу в очередь для повторной отправки.<br>12c. Заявка публикуется успешно. Пользователь получает информацию: «Заявка опубликована. Уведомления отправятся в ближайшее время». |
| Бизнес-правила | • BR-01: Создавать заявки могут только пользователи с ролями «Куратор» или «Приют».<br>• BR-02: Обязательные поля: тип помощи, заголовок, описание.<br>• BR-03: К одной заявке может откликнуться не более 1 исполнителя (статус меняется на «В работе»).<br>• BR-04: Заявка со статусом «Срочно» отображается вверху общего списка. |

## UC-4 — Подача заявки на пристройство животного

| Поле | Значение |
| - | - |
| ID | UC-4 |
| Название | Подача заявки на пристройство животного |
| Акторы | • Потенциальный владелец (авторизованный пользователь с ролью «Помощник»)<br>• Система<br>• Куратор или Приют (владелец карточки животного) |
| Предусловия | • В системе существует опубликованная карточка животного со статусом «Ищет дом»<br>• Карточка доступна для просмотра в каталоге |
| Постусловия (Успех) | • Заявка на пристройство сохранена со статусом «На рассмотрении»<br>• Куратор или приют (владелец карточки) получает уведомление о новой заявке<br>• Пользователь получает подтверждение: «Заявка отправлена. Куратор свяжется с вами»<br>• Событие зафиксировано в истории изменений карточки животного |
| Постусловия (Неудача) | • Заявка не создана<br>• Пользователю отображается сообщение об ошибке или причине отказа<br>• Введённые данные формы сохраняются для повторного редактирования |
| Основной поток | 1. Пользователь открывает каталог животных.<br>2. Система отображает карточки животных, доступных для пристройства.<br>3. Пользователь открывает карточку животного со статусом «Ищет дом».<br>4. Система отображает кнопку «Хочу взять животное».<br>5. Пользователь нажимает кнопку «Хочу взять животное».<br>6. Система отображает форму заявки на пристройство.<br>7. Пользователь заполняет обязательные поля: имя, контактный телефон, город проживания.<br>8. Пользователь при необходимости заполняет дополнительные поля: информация о жилищных условиях, опыт содержания животных, комментарий.<br>9. Пользователь нажимает кнопку «Отправить заявку».<br>10. Система валидирует данные: обязательные поля заполнены, номер телефона соответствует формату.<br>11. Система проверяет, не существует ли активная заявка с таким номером телефона на это животное.<br>12. Система сохраняет заявку с уникальным идентификатором формата ADOPT-XXXXX и статусом «На рассмотрении».<br>13. Система уведомляет куратора или приют о новой заявке.<br>14. Система отображает пользователю сообщение: «Заявка отправлена. Куратор свяжется с вами». |
| Альтернативный поток | **Заявка уже существует**<br>Точка входа: Шаг 11<br>11a. Система обнаруживает активную заявку с указанным номером телефона на это животное.<br>11b. Система отображает сообщение: «Заявка с этим номером телефона уже отправлена. Куратор свяжется с вами после рассмотрения».<br>11c. Новая заявка не создаётся.<br><br>**Пользователь авторизован в системе**<br>Точка входа: Шаг 6<br>6a. Система определяет, что пользователь авторизован.<br>6b. Система автоматически подставляет доступные контактные данные из профиля пользователя.<br>6c. Пользователь проверяет данные, при необходимости редактирует их и отправляет заявку.<br><br>**Куратор принимает или отклоняет заявку**<br>Точка входа: После создания заявки<br>1a. Куратор или представитель приюта открывает список заявок на животное в личном кабинете.<br>1b. Куратор просматривает данные заявки и связывается с потенциальным владельцем.<br>1c. После проверки куратор выбирает решение: «Принять» или «Отклонить».<br>1d. Система меняет статус заявки и фиксирует изменение в истории карточки животного. |
| Исключительный поток | **Статус животного изменился (уже пристроен)**<br>Точка входа: Шаг 3<br>3a. Статус животного изменён на «Пристроен» другим пользователем между открытием страницы и отправкой заявки.<br>3b. Система отображает сообщение: «Это животное уже нашло дом. Посмотрите других питомцев».<br>3c. Use Case завершается. Заявка не создаётся.<br><br>**Некорректные контактные данные**<br>Точка входа: Шаг 10<br>10a. Система обнаруживает, что обязательные поля не заполнены или номер телефона указан в неверном формате.<br>10b. Система отображает сообщение с указанием ошибки.<br>10c. Пользователь исправляет данные и повторно отправляет заявку. |
| Бизнес-правила | • BR-01: Просмотр каталога животных доступен без авторизации.<br>• BR-02: Подача заявки на пристройство доступна без регистрации при указании контактных данных.<br>• BR-03: Для подачи заявки обязательны имя, контактный телефон и город проживания.<br>• BR-04: На одно животное может существовать несколько заявок от разных пользователей.<br>• BR-05: С одного номера телефона нельзя подать более одной активной заявки на одно и то же животное.<br>• BR-06: Контактные данные заявителя доступны только куратору, приюту и администратору системы.<br>• BR-07: При смене статуса животного на «Пристроен» активные заявки по этому животному закрываются.<br>• BR-08: Для защиты от спама система может использовать CAPTCHA или ограничение частоты отправки заявок. |
